# Blog Publish Queue

## 현재 활성 큐: 2026-08-11 SEO/GEO 콘텐츠 갭 14개

현재 번호 배포 요청은 `active-plan.json`의 1~14번을 뜻합니다. 직전 활성 큐는 `archive/2026-08-seo-geo-authority.json`, 그 이전 큐는 `archive/2026-07-seo-geo-foundation.json`, 최초 발행 큐는 `queue.json`에 이력으로 보존합니다.

사용자가 `1번 배포해줘`처럼 요청하면 다음 순서로 처리합니다.

1. `active-plan.json`에서 번호별 제목, 메타 제목, slug, 썸네일 콘셉트와 내부 링크를 읽습니다.
2. 해당 동물 전용 Astro Markdown과 이미지 3~5개를 완성하고, 지정된 `file` 위치에 초안을 둡니다.
3. 배포 직전 한국 시간 날짜로 `pubDate`와 `updatedDate`를 설정합니다. `npm run publish:queued -- 1`은 이 두 날짜를 실행 당일로 다시 맞춥니다.
4. 빌드가 성공하면 커밋·push하고 Cloudflare Pages의 자동 배포를 확인합니다.

`publish:queued`는 활성 큐를 사용하며, 해당 글의 이미지 폴더도 함께 커밋합니다. 따라서 실제 배포 전에는 반드시 본문과 이미지가 생성되어 있어야 합니다.

## 발행 이력

이전 큐의 번호는 새 배포 요청에 사용하지 않습니다.

- `archive/2026-07-seo-geo-foundation.json`: 2026-07-27부터 2026-08-02까지 발행한 14개
- `archive/2026-08-seo-geo-authority.json`: 2026-08-03부터 2026-08-10까지 발행한 글과 미발행 후보 이력
- `queue.json`: 2026-07-20부터 2026-07-26까지 발행한 14개

## 배포 날짜 규칙

- 새 글을 배포할 때 `pubDate`와 `updatedDate`는 배포 실행일의 한국 시간 날짜로 맞춥니다.
- 기존 글을 수정 배포할 때는 원래 `pubDate`를 유지하고 `updatedDate`만 수정 배포일로 갱신합니다.
- `npm run publish:queued -- {번호}`도 새 글의 두 날짜를 자동으로 배포 당일에 맞춥니다.
- 이미지 생성, 의료 표현, 내부 링크, 중복 검사와 `npm run build`가 끝나기 전에는 push하지 않습니다.
